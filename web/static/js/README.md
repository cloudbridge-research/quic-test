# QUIC Dashboard JavaScript Modules

## Обзор
JavaScript код дашборда разделен на модульные файлы для лучшей организации, поддержки и масштабируемости.

## Структура файлов

### 1. `dashboard-core.js` - Основной модуль
**Назначение**: Главный класс QUICDashboard и инициализация
**Содержит**:
- Конструктор класса QUICDashboard
- Инициализация компонентов
- Привязка событий (event binding)
- Управление вкладками (tabs)
- Логирование и утилиты
- Периодические обновления

**Ключевые методы**:
- `init()` - Инициализация дашборда
- `bindEvents()` - Привязка обработчиков событий
- `initializeTabs()` - Настройка вкладок
- `log()` - Логирование сообщений
- `makeRequest()` - HTTP запросы
- `formatBytes()` - Форматирование размеров

### 2. `dashboard-charts.js` - Визуализация данных
**Назначение**: Интеграция с Chart.js и управление графиками
**Содержит**:
- Инициализация графиков Chart.js
- Обновление данных в реальном времени
- Сравнение протоколов QUIC vs TCP+TLS

**Ключевые методы**:
- `initializeCharts()` - Создание всех графиков
- `updateCharts()` - Обновление данных графиков
- `updateProtocolComparison()` - Обновление сравнения протоколов

**Графики**:
- Throughput Chart - Пропускная способность во времени
- RTT/Loss Chart - RTT и потери пакетов
- Protocol Comparison - Радарная диаграмма сравнения

### 3. `dashboard-scenarios.js` - Образовательные сценарии
**Назначение**: Управление интерактивными образовательными сценариями
**Содержит**:
- Выполнение пошаговых сценариев
- Отслеживание прогресса
- Образовательные инсайты
- Управление состоянием сценариев

**Ключевые методы**:
- `startScenario()` - Запуск сценария
- `initializeScenarioSteps()` - Настройка шагов
- `executeScenario()` - Выполнение сценария
- `updateScenarioInsights()` - Обновление инсайтов
- `completeScenario()` - Завершение сценария

**Сценарии**:
- Handshake Demo - Демонстрация рукопожатия
- Congestion Comparison - Сравнение алгоритмов перегрузки
- Stream Multiplexing - Мультиплексирование потоков
- Loss Recovery - Восстановление после потерь
- Migration Demo - Миграция соединений
- Security Features - Функции безопасности

### 4. `dashboard-export.js` - Экспорт и отчеты
**Назначение**: Функции захвата, экспорта данных и генерации отчетов
**Содержит**:
- Захват пакетов (Wireshark integration)
- Генерация PDF отчетов
- Экспорт данных в различных форматах
- Управление файлами

**Ключевые методы**:
- `startCapture()` / `stopCapture()` - Управление захватом
- `downloadPcap()` - Скачивание PCAP файлов
- `generateReport()` / `downloadReport()` - Генерация отчетов
- `exportData()` - Экспорт в CSV/JSON
- `convertToCSV()` - Конвертация в CSV

**Форматы экспорта**:
- PCAP - Для анализа в Wireshark
- PDF - Образовательные отчеты
- CSV - Табличные данные
- JSON - Структурированные данные

### 5. `dashboard-api.js` - Серверное взаимодействие
**Назначение**: Коммуникация с сервером и управление данными
**Содержит**:
- API вызовы к серверу
- Управление пресетами
- Обновление метрик
- Управление процессами QUIC

**Ключевые методы**:
- `loadPreset()` - Загрузка пресетов конфигурации
- `applyNetworkProfile()` - Применение сетевых профилей
- `getConfig()` - Получение текущей конфигурации
- `updateStatus()` - Обновление статуса
- `updateMetrics()` - Обновление метрик
- `startServer()` / `stopServer()` - Управление сервером
- `startClient()` / `stopClient()` - Управление клиентом
- `startTest()` / `stopAll()` - Управление тестами

## Архитектурные принципы

### Модульность
- Каждый файл отвечает за конкретную область функциональности
- Четкое разделение ответственности
- Легкость поддержки и расширения

### Расширяемость
- Методы добавляются к прототипу QUICDashboard
- Новые модули легко интегрируются
- Сохранение обратной совместимости

### Производительность
- Загрузка только необходимых модулей
- Оптимизированные обновления графиков
- Эффективное управление памятью

## Порядок загрузки

Файлы должны загружаться в следующем порядке:
1. `dashboard-core.js` - Основной класс (обязательно первым)
2. `dashboard-charts.js` - Графики
3. `dashboard-scenarios.js` - Сценарии
4. `dashboard-export.js` - Экспорт
5. `dashboard-api.js` - API (обязательно последним)

## Зависимости

### Внешние библиотеки
- **Chart.js** - Для создания графиков
- **Zitadel CSS** - Для стилизации

### Внутренние зависимости
- Все модули расширяют `QUICDashboard.prototype`
- `dashboard-core.js` должен загружаться первым
- `dashboard-api.js` использует методы из других модулей

## Использование

### Инициализация
```javascript
// Автоматическая инициализация при загрузке DOM
document.addEventListener('DOMContentLoaded', () => {
    window.dashboard = new QUICDashboard();
});
```

### Добавление новых методов
```javascript
// Добавление метода в любой модуль
QUICDashboard.prototype.newMethod = function() {
    // Реализация
};
```

### Доступ к экземпляру
```javascript
// Глобальный доступ к дашборду
window.dashboard.log('Custom message');
window.dashboard.startScenario('custom-scenario');
```

## Отладка


### Проверка состояния
```javascript
console.log(window.dashboard.activeScenario);

```

## Расширение функциональности

### Добавление нового сценария
1. Добавить конфигурацию в `dashboard-scenarios.js`
2. Обновить HTML с новой карточкой сценария
3. Добавить обработчик событий в `dashboard-core.js`

### Добавление нового графика
1. Создать canvas элемент в HTML
2. Добавить инициализацию в `initializeCharts()`
3. Добавить обновление в `updateCharts()`

### Добавление нового формата экспорта
1. Расширить метод `exportData()` в `dashboard-export.js`
2. Добавить конвертер данных
3. Обновить UI с новой кнопкой

## Лучшие практики

### Код
- Используйте `this.log()` для отладочных сообщений
- Проверяйте существование DOM элементов перед использованием
- Обрабатывайте ошибки в async операциях
- Используйте семантические имена методов

### Производительность
- Ограничивайте количество точек на графиках (max 20)
- Используйте `update('none')` для Chart.js без анимации
- Очищайте интервалы при завершении работы

### Совместимость
- Поддерживайте единый API между модулями
- Не изменяйте существующие методы без обратной совместимости
- Документируйте изменения в API
